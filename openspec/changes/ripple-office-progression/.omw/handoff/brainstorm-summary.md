## 确认的技术方案

### 布局与数据流

- 新增三层实际共用的布局数据模块，提供 seats、desks、xs、ys、nodes、patrolStops 和 scale；Game 与检查者保存当前布局，绘制及 DOM 点击区读同一数据，不修改全局座位数组。
- 8 座：两排双桌组，座位 y=360／680，横道 y=145／465／785，上下与排间留白均衡；保持现有角色比例；12 座：保留原坐标和比例。
- 16 座：四排双桌组，桌组中心 x=210／500，座位 y=240／420／600／780，局部比例 0.8，座位左右横偏移为 45×0.8。过道 x=65／355／655，横道 y=105／284／464／644／824。保持页面及 Canvas 尺寸不变。
- 家具、椅子和人物共同采用布局比例；声源和点击区使用实际座位锚点，提示文字维持可读字号。镜头不滚动。
- 寻路使用当前布局的相邻道路节点；巡视覆盖有效桌组并错开检查者起点，会议使用该布局的出口，联合预测复制并共用同一布局与模拟逻辑。

### 金椅

- 使用 specials 数组，每项包含 seat 和 left，所有 engine／render／app 的单椅读取点同步替换。
- 第十秒首次补齐上限；每把独立过期，后续每秒检查一次缺口并补齐，没有空位则等下一次，不逐帧重复运行寻路选择。
- 新金椅优先其他桌组，并沿用实际移动距离与可达时间优先逻辑。基础及连续奖金按当前座位是否命中金椅取 ×2，过期帧按有效时长分段，最多 ×2。
- 两把分别显示当前既有图标 ×2 和倒计时。被占用的有效金椅继续计时，过期后不能覆盖占用工位补刷。

### 水波纹

- 不增加贴图或依赖，以原生 Canvas 透明径向渐变、细边和短高光弧表达波光。线宽约 1.5～2.2 世界单位，去掉原 9 宽白底和 5.5 宽色边。
- 游戏约三层稀疏紫色波，蹦迪约五层暖金波；内部半径随 elapsed 的周期相位增长并淡出，全部限制在真实 radius 内，外缘保留细亮线。
- 范围先于人物绘制，蹦迪只在舞台上叠玩家自身范围，保持无检查者提醒；进度条和传出阈值保留，打印机与停手仍读取原声源状态。

### 存档与发布

- 沿用现有存档迁移写法，新版成绩键区分布局规则，解锁进度延续，旧记录不删除、不用于新版最佳比较。复核发现现有声音开关不跨刷新存储，保留当前开关行为，不新增声音持久化。
- 静态包白名单按实际新增布局模块扩充；测试、手机试玩后只发布运行文件，校验源提交、包及 HTTP 资源，保留上一版。

## 关键取舍与风险

- 比较过全图缩小、扩大地图滚动、局部布局重排；选择局部重排，保留观察全场和及时收手的体验。16 座人物约为现有八成，手机辨认和点选须实测。
- 比较过仅飘动弧线与完整细边加内部波纹；选择后者，避免美化后再次看不出范围。
- 更多空座可能降低检查密度；保持真实感知和速度，通过覆盖、种子回归及后两关完整试玩发现实际问题，不能用全知追踪弥补。
- 原生 Canvas 不引入每帧随机数、模糊滤镜或新音频处理，避免动画干扰随机预测和增加手机绘制成本。

## 测试策略

- 三种布局逐座互达、正交寻路及不穿桌，多个 Game 并存布局不串；巡视点覆盖、会议出口及反光镜联合预测一致。
- 金椅数量上限、分散桌组、空座不足、独立过期补刷、暂停、过期时间片收益与换座收手结算。
- 水波纹半径不超真实范围、多层扩散随模拟时钟变化、暂停不变化、无渲染副作用、打印机掩护与收手消失；声音进度保留。
- 运行全套测试与构建，适用美术检查；在 375×667 核对地图、点选、两把金椅及固定收手入口，完整试玩后两关、失败重来、暂停与主题事件。
