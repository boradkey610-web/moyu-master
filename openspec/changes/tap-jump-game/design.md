# 设计

引擎拥有独立的 runner 状态，由现有 `Game.tick` 推进。新模块 `src/runner.js` 包含小玩法物理、障碍与读取状态的 Canvas 绘制。首次进入先等待点击再开跑，保证第一次看到窗口时有学习时间。跳跃只有落地后可再触发，障碍失误清空小玩法连击并进入短暂恢复，办公室时间与巡逻继续。

打游戏按成功越过障碍发奖，单次基础奖励从 4 金币随连击增加至 8。连摸倍率按得分时的档位累积额外奖励，金椅同时作用于得分与连摸奖励。收手期间继续保留原活动风险，但停止接受跳跃和发放小玩法收入。等待点击、碰撞恢复、暂停均有明确提示。

界面位于操作区。打游戏期间压缩原活动按钮，窗口保持在办公室之外，一键工作始终可见且位置稳定。手机、桌面和窄屏遵循相同结构。保留上一轮第一关可蹦迪的改动。

用户追加了按钮和小游戏的视觉调整要求。最终复用办公室背景和主角步行动画，在桌面跳过文件、咖啡杯。活动卡片采用统一纵向排布，打游戏标为“点按闯关”。通过固定操作区网格和视口比例计算保持办公室完整、一键工作位置一致。收益反馈读取实际到账金额，打游戏关闭旧版按秒飘币。

成绩按新版收益规则分开保存，旧版仅继承解锁进度。模拟策略通过正常跳跃入口获得游戏收益。运行模块加入静态发布白名单。
