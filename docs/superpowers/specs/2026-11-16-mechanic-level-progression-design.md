# 六关机制递进技术设计

用户授权自主完成并由其后续验收，保持当前分支、主窗口测试先行、仅发布原公司开发机，不push不归档。

采用前四关专注机制、后两关组合的设计，而不是仅改名称或每关堆满所有事件。关卡配置显式events数组、goldSeats与rivals，布局不变。office包含meeting/printer独立子状态，混合时互不覆盖；自然会议使用独立种子随机和首次机会保底，复用sendToMeeting的正常寻路，不读取玩家位置。打印机声音、进度、提示和真实掩护统一读取printer子状态。联合预测继续深拷贝检查者及声场，共用事件推进，预测不消耗真实种子。

前三关关闭金椅计时和直接生成，第四关一把、后两关两把；前四关单老板，后两关双检查者，末关同事抢座。配置当前验证目标90/170/450/470/480/490，时长60/75/90/90/90/90，以固定30种子策略模拟检验并据结果调整；难度通过机制组合、人数和目标增加，不给全知追踪或突然提速。

选关插图复用老板、打印机、金椅、主管和玩家贴图，更新六关说明。测试版仍全部可选，三活动全关可用；开会通知第二关起优先补缺。v7存档继承v6进度及旧版本解锁，隔离旧成绩。

验证包含配置表、金椅门槛、概率与保底、事件重叠、真实听觉、暂停、预测、抢座、成绩迁移与选关内容；更新旧用例的主题夹具，保留原测试意图。完整回归、构建、独立审查和静态白名单发布，浏览器不可用时如实记录真实试玩缺项，不绕过连接限制。
